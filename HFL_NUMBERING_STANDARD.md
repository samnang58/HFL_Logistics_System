# HFL Logistics Numbering Standard

## Customer
- Customer ID: `HFL00001`, `HFL00002`, ...
- Generated by Laravel; users do not type it manually.

## Three logistics identifiers (must stay separate)

### 1. Container Number
- Physical container number.
- Example: `YCL268899`
- Database field: `containers.container_number`

### 2. HFL Tracking
- New HFL tracking number generated when China warehouse staff physically confirms receipt of the package.
- Example: `YC100200300`
- Database field: `packages.tracking_number`
- This is the main HFL tracking number used after China warehouse receipt.

### 3. China Delivery Tracking
- Original tracking number supplied by the China seller/courier/delivery company.
- Example: `8899006677100`
- Database field: `packages.china_waybill_number`
- This value must never be overwritten by the HFL tracking number.

## HFL Package Code
- Separate internal China-warehouse package code, when used by the operation.
- Example: `YC1000202930`
- Database field: `packages.hfl_package_code`
- It is not the China courier tracking number and not the container number.

## Operational example

- Container: `YCL268899`
- HFL Tracking: `YC100200300`
- China Delivery Tracking: `8899006677100`
- HFL Package Code: `YC1000202930`

These four identifiers are separate and must not overwrite one another.

## Search
Containers and Tracking support searching by:
- Container Number
- HFL Tracking
- China Delivery Tracking
- HFL Package Code
- Package ID
- Shipment Number
- Seal Number
- Customer

## Container movement
`Pending` → `Loading` → `Departed China` → `In Transit` → `Cambodia Port` → `Customs` → `Cambodia Warehouse` → `Received` → `Delivered`

## Customer ownership
- Sales Owner: selected from users whose role is `Sales`.
- Created By: automatically set from the authenticated Laravel user.
